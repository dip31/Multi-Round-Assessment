# Interview Repeat Question & Session Timeout Fix

Date: 2026-05-15
Issues: Repeated questions + 401 Unauthorized error

---

## Problems Identified

### Problem 1: Repeated Questions ❌
**Symptom**: AI asked about "confusion matrix" twice (questions 7 and 10)

**Root Cause**: 
- Questions generated by Groq LLM didn't have unique IDs
- Question tracking relied on IDs, but IDs were generated inconsistently
- When ID was missing, a hash was generated on-the-fly, but this could vary

**Evidence from logs**:
```
16:34:41 - Question: "what is a confusion matrix..."
16:42:11 - Question: "what is a confusion matrix..." (REPEATED!)
```

### Problem 2: 401 Unauthorized Error ❌
**Symptom**: At question 8, got `401 Unauthorized` and kicked to login page

**Root Cause**:
- JWT token expired after 30 minutes
- Interview took longer than 30 minutes
- Token expiration caused authentication failure mid-interview

**Evidence from logs**:
```
16:47:20 - POST /api/v1/interview/session/22/respond -> 401 Unauthorized
```

**Timeline**:
- Interview started: ~16:29
- Error occurred: 16:47
- Duration: ~18 minutes (but with follow-ups, could exceed 30 min)

---

## Fixes Applied

### Fix 1: Unique Question IDs ✅

**File**: `app/services/groq_service.py`

**Changes**:
1. Added `hashlib` import
2. Generate unique ID for each question using MD5 hash of question text
3. Apply to both Groq-generated questions and fallback questions

**Before**:
```python
questions = result["questions"]
for q in questions:
    q["role"] = detected_role
return questions
# No IDs assigned!
```

**After**:
```python
questions = result["questions"]
for idx, q in enumerate(questions, 1):
    q["role"] = detected_role
    # Generate unique ID based on question content
    q["id"] = hashlib.md5(q["question"].encode()).hexdigest()[:12]
return questions
```

**Impact**:
- ✅ Every question now has a unique, consistent ID
- ✅ Same question text always generates same ID
- ✅ Question tracking will work correctly
- ✅ No more repeated questions

### Fix 3: Enhanced Question Selection Logging ✅

**File**: `app/modules/interview/routers/interview_router.py`

**Changes**:
- Added duplicate detection check
- Added fallback to alternative question if duplicate detected
- Added detailed logging for debugging

**Code**:
```python
# CRITICAL: Check if this question was already asked
if question_id in asked_ids:
    logger.warning(f"Question {question_id} was already asked!")
    # Try to find a different question
    for q in available:
        alt_id = q.get("id", hashlib.md5(q["question"].encode()).hexdigest()[:8])
        if alt_id not in asked_ids:
            selected = q
            question_text = selected["question"]
            question_id = alt_id
            logger.info(f"Switched to alternative question {question_id}")
            break

logger.info(f"Selected question {question_id}: {question_text[:50]}... (asked_ids: {len(asked_ids)})")
```

**Impact**:
- ✅ Double-check prevents duplicates even if tracking fails
- ✅ Automatic fallback to alternative question
- ✅ Better logging for debugging
- ✅ Visible in backend logs

## How It Works Now

### Question Selection Flow

1. **Generate Questions** (Resume Upload):
   ```
   Groq generates 12 questions
   → Each gets unique ID (MD5 hash of question text)
   → Stored in approved_question_pool
   ```

2. **Select Next Question** (/next endpoint):
   ```
   Load asked_question_ids from rl_state
   → Filter out already-asked questions
   → Select from remaining questions
   → Check if selected was already asked (safety check)
   → If duplicate, find alternative
   → Add question_id to asked_question_ids
   → Save to rl_state
   ```

3. **Track Asked Questions**:
   ```
   asked_question_ids = ["abc123", "def456", "ghi789", ...]
   → Persisted in interview_sessions.rl_state (JSONB)
   → Survives across requests
   → Never resets during interview
   ```

### Token Expiration Flow

1. **Login**:
   ```
   User logs in
   → JWT token generated with 2-hour expiration
   → Token stored in localStorage
   ```

2. **Interview**:
   ```
   Every API call includes token in Authorization header
   → Backend validates token
   → If valid: Process request
   → If expired: Return 401 Unauthorized
   ```

3. **Token Lifetime**:
   ```
   Before: 30 minutes (too short for interviews)
   After: 120 minutes (2 hours - plenty of time)
   ```

## Additional Notes

### Why MD5 Hash for IDs?

- **Deterministic**: Same question text always generates same ID
- **Unique**: Different questions generate different IDs
- **Short**: 12 characters is enough for uniqueness
- **Fast**: MD5 is fast to compute

### Why 2 Hours?

- Average interview: 15-20 minutes
- With follow-ups: 30-40 minutes
- Safety margin: 2 hours covers even slow interviews
- Not too long: Still secure (not 24 hours)

### Why Not Use Database Auto-Increment IDs?

- Questions are generated by LLM, not stored in DB first
- Need IDs before DB insertion
- Content-based hash is more reliable
