2.2 Coding Round Lifecycle State Machine
Maps directly to assessment_rounds.status in the database. Frontend must read this from GET /coding/session/{id} response.
PENDING
Round not yet started
Trigger:
POST /session/start creates round row
UI Action:
Dashboard shows "Start Coding Round" CTA. Round Gate screen.
↓  ↓  ↓
ACTIVE
Timer running
Trigger:
POST /coding/start-round called
UI Action:
Full coding interface loads. Timer starts. Problem boxes visible.
↓  ↓  ↓
EXPIRED (auto)
Time ran out
Trigger:
datetime.utcnow() > end_time on any API call
UI Action:
Submit button disabled. "Time Up" banner appears. Redirect to result after 3s.
↓  ↓  ↓
COMPLETED
Round finished
Trigger:
POST /session/{id}/end OR auto-expire
UI Action:
Score animation plays. Redirect to /round/coding/result page.

Error State UX — Complete Failure Scenarios
Every error must have a defined UI response. "It depends" is not acceptable in a spec. These errors happen in real systems and candidates will encounter them.
3.1 Network & Server Errors
Scenario
Code
What UI Shows
Recovery Action
Network offline / fetch failed
ERR
Coral toast: "No internet connection. Your code is saved locally." Top banner stays visible.
Auto-retry every 10s. Toast updates to "Reconnected" when back.
API server 500 Internal Error
500
Coral toast: "Something went wrong on our end. Try again." Do NOT lose code.
Retry button in toast. Code in editor preserved via localStorage.
API server 503 Unavailable
503
Full-screen error overlay: "Platform temporarily unavailable" with live status indicator.
Show estimated time if available. Auto-poll every 30s.
Request timeout (>30s)
TIMEOUT
Amber toast: "Request is taking longer than expected." Spinner continues.
Cancel button appears after 30s. Code preserved.
401 Token Expired mid-session
401
Modal (not redirect): "Your session expired. Re-authenticate to continue." Timer PAUSES.
Inline re-login form in modal. Timer resumes after re-auth. Code preserved.
403 Round expired (time up)
403
Full-screen banner: "Time is up. Submissions are now closed." Submit button disabled.
Show final state. Redirect to results after 5s countdown.
403 Problem not assigned
403
Toast: "This problem is not part of your session." Redirect to problem 1.
Auto-redirect. Do not show error code to candidate.
404 Round not found
404
Full-screen error: "Session not found. Please start a new assessment."
Back to Dashboard button.

Scenario

What UI Shows

Retry button. Submission NOT stored. Candidate can resubmit when available.

3.3 Error State Design Rules
NEVER show raw HTTP status codes to candidates — use human language
ALWAYS preserve code in editor across any error — use localStorage as backup
NEVER redirect away from coding round on transient errors (network blip, 500)
ALWAYS show retry option for recoverable errors
401 mid-session MUST use a modal, not a redirect — redirect loses the session context
Use a global error boundary in React to catch unexpected crashes
Log all errors to console in dev, to monitoring service (Sentry) in production

Mobile Strategy — Coding Round Blocking
Coding IDEs on mobile devices deliver universally poor UX. Industry standard (LeetCode, HackerRank, AMCAT) is to block the coding round on mobile and redirect to desktop.
5.1 Device Detection Strategy
Device Category
Viewport Width
Coding Round Behavior
Mobile Phone
< 768px
BLOCKED. Show desktop redirect screen. Timer does not start.
Tablet Portrait
768px – 1023px
BLOCKED. Same desktop redirect screen.
Tablet Landscape
1024px – 1279px
WARNING only. Full interface loads but banner: "Best experienced on 1280px+ screen".
Desktop / Laptop
1280px+
FULL experience. No warnings.
External Monitor
1440px+
OPTIMAL experience. All three panes at full width.
5.2 Mobile Block Screen Implementation
Detect viewport on route entry using window.innerWidth and navigator.maxTouchPoints
Store detection result — do not re-check on every render (performance)
Block screen shows: large monitor icon, explanation text, two buttons
"Send link to email" button: sends candidate the round URL to open on desktop
"Back to Dashboard" button: returns without starting the round
CRITICAL: timer does NOT start until user is on a valid device and clicks Start Round
If candidate starts on desktop, then resizes below 768px: show overlay warning, disable Submit button, timer continues

6.2 Polling Strategy
Polling is used for timer sync and problem status updates. Over-polling wastes resources.
What
Interval
Implementation
Timer sync (GET /session)
60 seconds
Use setInterval. Stop polling when round.status != "active". Use server time_remaining_seconds, not Date.now() delta.

30 seconds

Session status (Dashboard)
On mount only
No polling on dashboard. Fetch once, no stale data risk.
Submission result
No polling needed

6.3 Monaco Editor — Memory Management
Load Monaco only on /round/coding route — use Next.js dynamic import with ssr: false
Dispose Monaco instance on route unmount to prevent memory leak: editor.dispose()
Save code to localStorage on every keystroke debounced at 500ms
Switch between problems: save current code to localStorage keyed by problem_id, load new problem code
Maximum localStorage per problem: 50KB — enforce limit with length check before save
Do NOT use Monaco for the mobile fallback — use plain textarea

7.1 Key Architectural Rules
RULE 1: No component imports from a sibling feature folder. coding/ never imports from aptitude/.
RULE 2: shared/ components have zero business logic — pure UI only.
RULE 3: All API calls go through lib/api.ts — never call fetch directly in components.
RULE 4: All backend response types defined in types/api.ts — must match Pydantic schemas exactly.
RULE 5: All string constants (status values, verdicts) defined in lib/constants.ts — never use raw strings.
RULE 6: Hooks folder owns all stateful logic — components are UI shells that use hooks.
